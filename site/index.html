01 定位

复杂问题需要的，不是更响亮的结论，而是可检查的方法。

Ariadne 是什么

Ariadne 是一个独立的方法论 Skill 集群。它把复杂请求整理成有边界、可追踪、可续接的方法运行：先说明现实问题，再冻结候选对象与证据截止点，只调用足够的模块，并把冲突、未知和证据上限原样保留下来。

它既可由总路由协调，也允许九个模块被单独点名。模块数量不会制造证据，流程完成也不会制造授权。

Ariadne 不是什么

  • 不是关于世界本身的本体论。
  • 不是真理引擎、人格裁判或临床工具。
  • 不替主体选择价值，也不把预测写成命令。
  • 不是现实行动、资源处分或公共权力的授权机关。

02 Lattice Kernel

一张按需展开的方法地图。

共同内核规定对象、证据、缺失状态、谱系与输出上限；具体模块只处理自己负责的判断环节。

  1. 总路由：分类请求，选择最小充分模块集。
  2. 共同冻结：由 ariadne-framing 与 ariadne-evidence 固定候选对象和证据截止点。
  3. 可并行分析：ariadne-scale、ariadne-mechanism、ariadne-human 在共享冻结记录上独立工作。
  4. 按需进入：路径推演、可检验前瞻和有限选择各自保持边界。
  5. 合并与治理：ariadne-audit 保留冲突，按最低输出上限合并并检查停止、申诉和回滚。

03 十个方法论模块

每个模块只守住一个判断环节。

下面的五字段卡片来自仓库中的权威 Skill 合同。它们帮助选取模块，不替代合同本身。

00 · 总路由

Ariadne

ariadne-skill
负责什么
把复杂请求变成有边界、可检查的方法运行，分类输出并按需路由。
可以完成
冻结对象与证据、选择最小模块集、协调顺序或并行工作、保留冲突并合并 Method Record。
适合任务
同时涉及解释、机制、尺度、未来、选择或高影响审查的复合问题。
典型产出
一份先说人话的有限判断，以及可追踪的模块运行、证据截止点、未知项和下一步。
边界
不是本体论、真理引擎、价值选择器或授权机关；不会因模块更多而提高证据。
01 · 问题定界

Framing

ariadne-framing
负责什么
在判断之前说明究竟在分析什么：边界、变量、接口、时间、尺度和身份标准。
可以完成
分类请求，冻结候选对象，分开描述、诊断、前瞻、选择和现实行动。
适合任务
对象含糊、范围漂移、同词跨尺度，或用户把解释与行动混在一起的问题。
典型产出
候选对象陈述、未决边界选择，以及保留父记录的定界版 Method Record。
边界
完整定界不证明对象真实稳定；止于 description_only，不输出诊断、建议或许可。
02 · 证据审计

Evidence

ariadne-evidence
负责什么
区分来源、材料、观察、证据、反证、判断与外部授权，检查主张被支持到哪里。
可以完成
冻结证据窗口，拆分主张类型，审计因果、类比、基线、替代解释和零结果条件。
适合任务
需要核查引用、数据、观察、因果故事、类比或证据强度的工作。
典型产出
主张账本、支持与反证链、未决替代解释、证据强度判断和后续取证要求。
边界
相关性与顺序不自动成为因果；经验置信度不生成价值、责任、建议或授权。
03 · 尺度转换

Scale

ariadne-scale
负责什么
审计对象、观察或主张跨个体与群体、时空、圈层、表征和词汇时发生的变化。
可以完成
冻结源端与目标端，逐轴比较，记录映射、保留项、损失、误差和不可迁移项。
适合任务
从个体推群体、短期推长期、局部推全局、摘要压缩或跨领域迁移。
典型产出
尺度剖面、原子转换记录、身份映射、损失审计与目标侧证据要求。
边界
共享名称不是桥；更大范围、更多观察、地位或网络中心性都不扩大管辖权。
04 · 机制比较

Mechanism

ariadne-mechanism
负责什么
以最简单充分基线为参照，比较通道、反馈、约束与竞争机制。
可以完成
为候选机制登记通道观察、区分性预测、反转条件、证伪标准和剩余误差。
适合任务
需要解释差异、负载、反馈、学习、阈值、选择或持续性的结构诊断。
典型产出
简单基线、至少两个完整候选机制、残差比较和可区分的下一项观察。
边界
机制标签不是证据；少于两个完整候选时止于描述，不分配价值、责任或许可。
05 · 人类领域

Human

ariadne-human
负责什么
在分析人与组织时分开角色、权力、隐私、责任、意义、多重归属与物质条件。
可以完成
登记观察位置与允许用途，比较替代解释，审计受影响、低权力和无退出位置。
适合任务
关系、团队、组织、制度、公共互动，以及含敏感材料或权力不对称的问题。
典型产出
有隐私边界的角色与圈层记录、候选解释、受影响位置和负责的人类复核要求。
边界
不把行为、沉默或拒绝写成人格与临床诊断，不把集体当作一个人，也不推定同意。
06 · 动态推演

Dynamics

ariadne-dynamics
负责什么
从冻结状态推导事件如何沿通道、时钟、阈值与反馈形成条件路径。
可以完成
区分事件事实状态，展开有向无环分支，登记信号、残差、停止条件与结果回写。
适合任务
事件传播、异步时钟、情景、反事实、递归模拟与低概率高后果分支。
典型产出
冻结快照、带条件的路径图、早期与反向信号、竞争分支和残差出口。
边界
模拟深度不生成证据；报告、计划、假设和模拟事件不冒充已观察事实或前瞻。
07 · 条件前瞻

Forecast

ariadne-forecast
负责什么
在结果出现前登记有目标、有期限、可判断、可校准且能够失败的未来主张。
可以完成
冻结输入与评价规则，设置公平简单基线，登记信号、失败状态与追加式回写。
适合任务
有明确目标和截止日期的条件判断、基线比较、校准和结果复盘。
典型产出
前瞻 ID、目标与期限、条件路径、最弱充分表达、评价规则和下次复核点。
边界
不回填式预注册，不从文字或模型信心捏造概率；前瞻准确也不产生行动权。
08 · 有限选择

Choice

ariadne-choice
负责什么
在有限选项中比较行动、等待、可逆实验、退出或转交，以及明确的不行动。
可以完成
分开事实与价值，比较后果、分布、可逆性和锁定，检查管辖、停止、申诉与回滚。
适合任务
个人选择、治理程序、试点、退出与资源受限且需要保留保护底线的决定。
典型产出
同基线选项卡、价值冲突、受益与负担位置、外部授权缺口和保护性不行动。
边界
不替主体选择价值，不从沉默或未退出推定同意，不签署授权，也不执行选项。
09 · 审计与治理

Audit

ariadne-audit
负责什么
检查高影响判断、自动化输出、公共主张和完整方法记录能否保留当前判断与用途上限。
可以完成
按序运行闸门，标记失败与未运行项，检查申诉、反报复、纠正、回滚、补救与退役。
适合任务
公开、组织、制度、自动化、难逆使用，以及多模块结果的合并与治理。
典型产出
闸门发现、受影响主张、降低后的输出上限和可到达的异议与纠正路径。
边界
表格完整、文字流畅、内部测试和自审都不证明现实有效、安全、同意或授权。

04 协作方式

五种运行方式，按任务而不是按仪式选择。

01

单独

直接调用一个模块，完成一个边界清楚的定界、证据、尺度或其他专项任务。

02

连续

当前一环的输出是后一环的真实输入时顺序执行，并保留父记录、版本和改变原因。

03

集群

对象与证据截止点一致后，让尺度、机制或人类领域独立工作；合并时不投票、不平均冲突。

04

持续

通过追加式子记录接纳新证据、结果和反例；对象或用途改变时从最早受影响闸门重跑。

05

完整运行

复杂或高影响任务由总路由组织完整方法流程，但仍只运行最小充分模块集。

集群前置条件

所有工作者必须接收同一份原始任务、冻结对象、证据截止点、责任边界和输出字段；不得预先给出偏好的结论。

05 Method Record

让一次推理可以被继续、质疑和降级。

Method Record 不是结论包装，而是对象、证据、主张、谱系、未知项、模块运行与输出边界的共享记录。

最小边界示意

request_type: diagnosis
object_status: candidate
evidence_cutoff: 2026-08-05
unknowns:
  - channel_not_observed
output_ceiling: diagnostic_only
authorization_effect: none

四种缺失状态

unknown
当前不知道，仍可能通过合适方式补充。
not_applicable
在这个对象或任务中不适用。
not_observable
在当前观察条件下不可见。
withheld_for_protection
为隐私或安全而不披露，不得被推断填满。
输出上限允许表达仍然不允许
description_only描述候选对象、材料、未知项和需要补足的条件。把对象存在、因果或行动写成已成立。
diagnostic_only给出有边界的证据、机制、转换或缺陷判断。把诊断自动升级为建议、处分或许可。
requirements_only列出外部选择、复核、纠正或撤回仍须满足的要求。替外部主体完成价值选择、授权或执行。

始终为零authorization_effect: none。无论完成多少模块、得到多高置信度或通过多少内部闸门，都不会产生现实授权。

06 六宿主安装

同一套权威 Skill，面向六种 Agent 宿主。

默认安装完整十模块。当前没有稳定 tag，以下命令跟随 main，属于滚动安装；Windows 使用复制模式，不依赖符号链接。

宿主兼容等级主要发现位置说明
Codex / OpenAI原生 Agent Skills.agents/skills、用户 Skill 目录保留 OpenAI metadata 与显式调用。
Claude Code原生 Agent Skills.claude/skills支持目录发现、引用文件和斜杠调用。
Gemini CLI原生 Agent Skills.gemini/skills 或 .agents/skills调用前仍由宿主决定激活授权。
Cursor原生 Agent Skills.cursor/skills、.agents/skills、.claude/skills 或 .codex/skills支持自动发现与显式调用。
GitHub Copilot原生 Agent Skills.github/skills 或 .agents/skills云端、CLI 与编辑器表面可能不同。
Reasonix目录兼容子集.reasonix/skills、.agents/skills 等不声明隐式路由等价，需专项冒烟验证。
项目级 · 推荐试用

安装完整十模块

npx skills add xi-kari/ariadne-skill --skill '*' --copy -a codex -a claude-code -a gemini-cli -a cursor -a github-copilot -a reasonix

放入当前项目，便于审查、试用和随项目共享。

用户级 · 跨项目使用

全局安装完整十模块

npx skills add xi-kari/ariadne-skill --skill '*' --copy --global -a codex -a claude-code -a gemini-cli -a cursor -a github-copilot -a reasonix

由安装工具写入各宿主的用户级目录，适合跨项目持续使用。

显式降级

仅安装主路由

npx skills add xi-kari/ariadne-skill --skill ariadne-skill --copy -a codex -a claude-code -a gemini-cli -a cursor -a github-copilot -a reasonix

只有明确接受降级时使用。缺失 peer 必须记录 module_unavailable，不得假装该模块已经运行。
