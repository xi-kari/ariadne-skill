# Ariadne 中文 README 重设计说明

## 状态

- 视觉方向：已批准 C「理性格点」。
- 首屏定位：已批准“**一套让 AI Agent 思考和处理复杂问题的方法论集群。**”
- 实施范围：仅修改仓库 README，并新增其直接使用的 SVG 视觉资源。

## 目标

把当前英文工程摘要改造成一页中文方法论介绍。读者应能在不打开各模块内部文件的情况下理解：

1. Ariadne 是什么、为什么存在，以及 Lattice Kernel 负责什么。
2. 一个总路由与九个平级模块如何独立、连续或集群工作。
3. 十个方法论 Skill 分别负责什么、能完成哪些工作、适合哪些任务、止于什么边界。
4. 如何在当前电脑上显式调用、验证和继续阅读。

README 参考 CrossFrame 的成熟阅读节奏，包括全宽首屏、状态徽章、概览条、编号目录、分层表格和章节回链；不得复制 CrossFrame 的品牌、标语、专属数字、运行链或产品定位。

## 受众与成功标准

主要受众是需要处理复杂问题的 Agent 使用者、Skill 作者、研究者和希望借用方法论思考的人。

成功标准：

- 首屏一句话说明“方法论集群”和 AI Agent 的用途。
- 十个 Skill 均有独立介绍，且职责不互相越权。
- 普通读者能快速找到适合自己的模块，工程读者能找到调用、验证与合同入口。
- 明确 Ariadne 不是世界本体论、真理引擎、人格或临床诊断工具、价值选择器或现实授权机关。
- README 的所有能力描述都能在仓库现有 Skill 合同中找到依据。

## 视觉系统

采用 C「理性格点」：冷白纸面、深青文字、紫色节点与铜色强调，表达模块化方法、可追踪路径和清晰边界。

| 角色 | 色值 | 用途 |
|---|---|---|
| 纸面 | `#EDF2EF` | SVG 背景与大面积留白 |
| 主墨色 | `#173532` | 标题、主线和核心节点 |
| 格点线 | `#B7CBC4` | 网格、分隔和关系线 |
| 节点紫 | `#8B62AD` | Ariadne 标点、关键节点和层级强调 |
| 铜色 | `#C4874F` | 边界、警示和授权限制 |

中文标题使用衬线字体回退栈，元信息与 Skill ID 使用等宽字体回退栈。视觉应保留纸面编辑感，但比 CrossFrame 更现代、更模块化。

新增两项资源：

- `docs/assets/readme-hero.svg`：Ariadne、Lattice Kernel、核心定位与格点线索意象。
- `docs/assets/lattice-kernel-map.svg`：一个总路由、基础冻结层、可并行分析层、路径与未来层、选择与审计层；必须标注“按需选取”，避免暗示每次强制全跑。

两个 SVG 都提供中文 `aria-label` 和 README 替代文本。结构图后提供文本版，确保无图环境仍能理解。

## README 信息结构

1. **首屏**：Hero、品牌名、中文定位、简短说明、状态徽章和关键入口。
2. **事实概览条**：十个 Skill、`1 + 9` 架构、五种协作模式、`authorization_effect: none`。
3. **编号目录**：章节名与一句话说明。
4. **Ariadne 是什么**：方法论集群定位，以及“不是什么”。
5. **Lattice Kernel 方法论地图**：模块关系、按需路由和共同合同。
6. **十个方法论总览**：用一张简表帮助读者快速选模块。
7. **十个方法论详解**：每个模块使用完全一致的介绍模板。
8. **如何组合工作**：单独、连续、集群、持续、完整方法运行及典型链路。
9. **Method Record 与输出边界**：可续接记录、输出上限、未知与冲突、现实授权边界。
10. **调用与验证**：全局分发语义、当前电脑的显式点名限制、验证命令。
11. **文档与仓库状态**：设计、覆盖、验证入口和发布边界。

所有说明、标题、表格和徽章使用中文；仅保留 `Ariadne`、`Lattice Kernel`、`ariadne-*`、字段名与命令等固定技术标识。

## 十个方法论卡片

每个详细模块固定回答五件事：

| 字段 | 说明 |
|---|---|
| 负责什么 | 该模块守住的判断环节 |
| 可以完成 | 它能直接执行的方法工作 |
| 适合任务 | 典型问题、材料或工作场景 |
| 典型产出 | 用户或下游模块会得到什么 |
| 边界 | 它明确不做什么、何时转交下一模块 |

卡片的中文定位如下：

| Skill | 中文定位 |
|---|---|
| `ariadne-skill` | 方法论总控：拆解复杂任务、按需路由并合并结果 |
| `ariadne-framing` | 问题定界：先确定究竟在分析什么 |
| `ariadne-evidence` | 证据审计：判断材料能把主张支持到哪里 |
| `ariadne-scale` | 尺度转换：检查跨个体、群体、时空和领域的迁移 |
| `ariadne-mechanism` | 机制比较：让基线、通道和竞争解释接受检验 |
| `ariadne-human` | 人类领域约束：处理角色、权力、隐私、责任与意义 |
| `ariadne-dynamics` | 动态推演：展开事件、时钟、阈值、反馈和分支 |
| `ariadne-forecast` | 条件前瞻：把未来判断登记成可校准、可失败的主张 |
| `ariadne-choice` | 有限选择：比较做、等、试、退与不行动 |
| `ariadne-audit` | 审计与治理：检查强判断、申诉、降级、回滚和退役 |

详细文案必须来自对应 `SKILL.md` 与直接合同引用。不得让动态推演冒充前瞻，不得让前瞻替主体选择，不得让选择或审计生成现实授权。

## 交互与阅读节奏

- 每个主章节使用稳定锚点、编号、小号中文眉题和“返回目录”。
- 总览表负责快速选择，详细卡片负责完整解释；不把两者合并成一张过宽表格。
- 代码块仅用于调用、组合链路和验证命令。
- 工程状态从首屏下沉到末尾，避免开发阶段信息压过方法论用途。
- 不展示开发日记、迭代叙述或模块施工过程。

## 实施边界

- 不修改任何 Skill 合同、schema、验证器或 eval。
- 不修改 CrossFrame 仓库，也不复制其 SVG。
- 不新增网页、Release、License、安装器或全局安装步骤。
- 当前电脑只说明显式 Skill 名或仓库路径调用，不写入全局 Skill 目录。
- 不宣称表格完整、闸门通过、模块一致或 AI 生成等同于事实、有效性、安全、同意或授权。

## 实施与审查顺序

遵守“先完整建设、后统一审查”：

1. 一次性完成 README 全部中文内容与两个 SVG。
2. 确认十个模块均已完整出现，形成 `README_CONTENT_COMPLETE` 边界。
3. 只在完整边界之后开始统一内容审查、视觉审查、链接审查和合同一致性审查。
4. 集中修正发现的问题。
5. 最后运行仓库验证并检查 Git 差异。

实施阶段不得一边写单个模块、一边把它当作已审定内容逐个验收。
