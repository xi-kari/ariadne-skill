# Ariadne 架构：从问题走到成果

Ariadne 只有一个安装入口：`ariadne-skill`。Lattice Kernel 把方法组织为可组合的操作、工作路径、共同责任和按需读取的理论资料。路径从用户想得到什么出发，可以改变顺序、组合、分叉和回到先前问题；它们不是理论章节的逐一翻译，也不是必须完整走完的流水线。

## 四种不同的角色

| 层 | 内容 | 使用方式 |
|---|---|---|
| 入口与工作路径 | `SKILL.md`、`paths/` | 识别当前任务，选择能够交付结果的路径，并随新材料调整 |
| 共同方法 | `references/kernel.md`、`composition.md`、`responsibility.md`、`continuity.md` | 保持问题、证据、条件、判断、授权和成果接续之间的关系 |
| 理论资料库 | `references/library/` | 在具体命题需要时读取完整的专门条件、反例、变量卡和来源锚点 |
| 专用制品 | `contracts/`、`scripts/` | 在任务要求冻结、登记或交换时使用适当的结构和工具 |

[architecture.json](../skills/ariadne-skill/architecture.json) 声明资源、入口、路径和单文件版顺序。验证器检查资源存在、路径安全、可达性与重复项，不固定路径数量。资源可达不意味着已被模型读取；单文件版也不假装嵌入了未包含的深库或工具。

## 路径与成果

| 起点 | 可以形成的成果 | 有用的接续 |
|---|---|---|
| 理解 `understand` | 清楚的概念区分、文本解释、条件证明、经验解释 | 从解释中发现新问题，或审查解释依赖 |
| 发现 `discover` | 新问题、反例、候选机制、可检验的设计 | 将候选变成推演、比较或实际原型 |
| 推演 `project` | 条件路径、反事实、转折条件；必要时正式前瞻 | 找到应观察什么、何时切换或停止 |
| 取舍 `decide` | 有条件的建议、可比较的方案、制度草案 | 完成方案，并保留损失、责任和复核安排 |
| 构建 `create` | 实际文档、代码、排班、规则、原型或修复 | 检查成品端点，根据新要求直接修订 |
| 复核 `review` | 反例检验、依赖修正、失败定位、修订或退役决定 | 保留仍成立的部分，重开受影响的问题 |

六条路径是当前提供的起始配方，不是封闭的能力分类。例如，写一份简单说明可以直接完成；制度设计可以同时展开几种价值取向；发现更合适的问题可以回到理解；修复程序也未必需要推演和规范取舍。

## 组合如何产生能力

**解释 → 新问题 → 可检验设计。** 如果学习进步成立而就业改善未出现，保留学习结果，检查能力如何经过准入、时间、资源和岗位条件转化为机会，再形成能够区分这些解释的观察或试验。

**断点 → 条件替换 → 成品。** 总工时足够但同时段人手不足，缺口在可用时段和共同容量。替换任务时间或分配规则，生成排班文件，并检查每天覆盖与每个人的负担。

**反事实 → 切换条件 → 持续修订。** 明确改变哪个条件、哪些下游关系随之变化，找出当前模型范围内足以改变结果的条件。新增材料到来后只重算受影响的依赖，保留旧判断在原条件下的状态。

**规范分歧 → 平行制度草案 → 有限建议。** 保持事实基础一致，分别展开不同的优先规则，比较保护、负担、可行性和剩余请求。所有可行方案都有损失时仍可作出明确的条件建议，并写出救济和复核责任。

这些是 Ariadne 的派生工作编排，不是新增的原文定理。生成的新候选保留候选身份；形式证明依其前提成立；真实作用需要相应的现实证据。

## 不同责任不能压成一个等级

一个任务可以同时拥有成立的局部结果、未识别的整体机制、可用的草案和尚未发生的部署。合并工作时逐项检查依赖，保留独立成立的结果。材料质量、因果识别、形式有效性、规范理由、外部授权和实际完成情况分别记录到需要的程度。

普通回答和成品使用合适的自然语言、表格或文件，不强制填统一记录。正式前瞻使用[专用合同](../skills/ariadne-skill/contracts/forecast.md)：结果揭晓前冻结目标、材料、比较基线、表达类型和评价办法；结果到来后追加观察。工具检查格式与文件行为，不能验证来源事实、生成行动授权、自动证明预测能力或代替后续观察。

原文部分专门程序本身含有严格记录条件，例如状态原型运行、干涉和前瞻。资料库保留这些条件及等价程序的实质责任。旧 Method Record 2.0/2.1 则仅在明确需要旧交换格式时启用，见[迁移说明](migration.md)。

## 持续协作与交付

接续围绕当前问题、已有材料、有效判断、实际成果、变化原因和下一检查点展开。更新约束要更新成品；写入后要读回；外部操作完成后要检查实际状态。已有有效授权在其范围内继续适用，方法本身不另造授权。

停止条件取决于完成端点、真实阻碍和任务预算，不设所有任务统一的轮数。没有安排工具或责任人时，不承诺后台监测或自动复核。
