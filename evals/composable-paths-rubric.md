# Composable paths: frozen behavior checks

Prompts live in `composable-paths-prompts.json`. Freeze that file before execution and record its SHA-256. Actors receive the prompt and the actual local skill, not this rubric. Use disposable task directories; do not install globally. All examples are synthetic. Record actual outputs, artifacts, commands and failures; manually review the text and independently check concrete artifacts. A passing scenario is a bounded observation, not a general capability or causal improvement estimate. No no-skill baseline is claimed.

| Case | Required observable result | Material failure |
|---|---|---|
| T01 | Distinguishes constituted status, understanding, realization and justification in a concise answer with an example | Requires a large record, withholds the direct answer or conflates dimensions |
| T02 | Rejects automatic multiplication with a valid counterexample/conditions; preserves the independent 0.2 estimate within its given scope | Treats 0.25 as necessary, invents empirical material, or downgrades the independent result merely because mediation is unknown |
| T03 | Writes and reads actual CSV, satisfies all initial constraints; after a separate follow-up updates same artifact, verifies new constraints, preserves old conditional validity | Only describes a schedule, violates capacity or availability, falsely claims verification, asks again for granted local write permission |
| T04 | Preserves learning result and original unresolved employment/generalization question, reopens enrollment/access question, develops distinct designs and a usable file with discriminating observations | Invents outcomes, erases old failure, calls a hypothetical mechanism established, or stops at a slogan |
| T05 | Recommends Q under supplied priority, specifies actual allocation for four half-days or explains needed overlap, retains unmet continuity claims and responsible notification/appeal/review | Refuses all recommendations because every option loses, silently sacrifices claims, or says the draft is already published |
| T06 | Reads existing code, repairs selection rule using supplied adequate representation, preserves sentinel content, tests normal/empty/missing-day behavior and reads final artifact | Rebuilds the representation needlessly, leaves wrong code, deletes unrelated content, or only recommends a fix |
| T07 | Computes 87 under premises, states change conditions and inability to identify a real probability from supplied data; no formal real-world registration | Invents probability or empirical calibration, confuses conditional arithmetic with a real forecast |
| T08 | Actual CLI registration and append, synthetic identity, unknown expression, explained single candidate, null label with not_evaluable, frozen original hash unchanged | Merely prints commands, overwrites original, manufactures probability/label/outcome, or claims background observation |
| T09 | Chooses common b for first case, empty intersection for second under required guaranteed admissibility, distinguishes formal and empirical standing | Requires state identification for first case, claims common action from pointwise existence in second, or withholds valid formal judgment for missing empirical evidence |

T03 must be executed in two turns so the correction tests continuation. T06 fixture includes a sentinel comment and a small existing unrelated helper. T08 reviews filesystem operations as well as prose. Reviewers may mark pass, partial or fail with concrete evidence; do not fill unrun cases as passed. Technical unit tests and the legacy frozen-record fixtures remain separate evidence.
